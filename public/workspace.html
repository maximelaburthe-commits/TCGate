Maintenance des bases de données

Actions GitHub · validation humaine

GitHub Actions automatise ; la Pull Request porte la validation humaine. Chaque partie utilise un SHA DB immuable.

Cycle de maintenance et prochaine étape

Source fiable → fetch → snapshot immuable → diff → staging → build → validation → branche update/… → Pull Request → validation humaine → merge.

DB main mise à jour ≠ TCGate automatiquement mis à jour. L’intégration d’un SHA DB dans TCGate reste une opération séparée.

Prochaine étape dans le repository Cyberpunk : workflow « Update Cyberpunk DB ». La PR présentera cartes/printings avant et après, nouvelles locales, assets nouveaux/modifiés, IDs existants modifiés, modification éventuelle du runtime actif et résultats des tests. Même architecture ultérieurement pour SWU.

Priorité des sources : API/export officiel, backend structuré officiel, API tierce qualifiée, données structurées du site, HTML en dernier recours, correction manuelle exceptionnelle. Aucune source externe n’est utilisée directement en partie.
